Anthropic 7 standards

anthropic-clarity Medium

The file VIOLATES if instructions are vague or ambiguous where a concrete directive is needed (e.g. "be helpful", "handle errors well" with no specifics).

Why it matters — Vague asks produce vague behavior; models follow specifics.

anthropic-examples Medium

VIOLATES if non-obvious conventions, formats, or behaviors are described without at least one concrete example.

Why it matters — One example beats three sentences of description.

anthropic-delimit-sections Low

VIOLATES if the file mixes unrelated concerns in one undifferentiated block with no headings, tags, or delimiters separating sections.

Why it matters — Structure tells the model what belongs together.

anthropic-data-vs-instructions Medium

VIOLATES if variable or contextual data is tangled directly into directives instead of being clearly marked as data.

Why it matters — Unmarked data gets treated as instruction, and vice versa.

anthropic-allow-idk High

VIOLATES if the file asks the agent to produce facts, APIs, file paths, or commands but never tells it to admit uncertainty or avoid inventing details.

Why it matters — The #1 defense against hallucinated paths and APIs.

anthropic-positive-framing Low

VIOLATES if guidance is expressed almost entirely as prohibitions ("don't…") without stating the desired behavior to do instead.

Why it matters — Models steer better toward stated targets than away from bans.

anthropic-context-placement Low

VIOLATES if long reference material or background is placed in the middle of actionable instructions rather than grouped at the end or in its own section.

Why it matters — Mid-stream reference dilutes the directives around it.

OpenAI 8 standards

openai-identity Medium

VIOLATES if the file never states the agent's purpose, role, or the project it serves.

Why it matters — Identity anchors every downstream decision.

openai-dos-and-donts Medium

VIOLATES if behavioral rules are stated only abstractly without explicit dos and don'ts the agent can follow.

Why it matters — Abstract values don't constrain concrete actions.

openai-example-consistency Low

VIOLATES if examples in the file use inconsistent formatting or contradict each other.

Why it matters — Contradictory examples train contradictory behavior.

openai-structure Low

VIOLATES if the file lacks any markdown headers or hierarchy and is hard to scan for distinct topics.

Why it matters — Both humans and models navigate by structure.

openai-explicitness High

VIOLATES if the file relies on the agent inferring critical requirements (stack, commands, constraints) that are never stated outright.

Why it matters — What isn't stated will be guessed — sometimes wrong.

openai-context-early Low

VIOLATES if static, reusable context (project facts, conventions) is buried at the end after volatile task detail rather than established up front.

Why it matters — Stable facts up front frame everything after them.

openai-agentic-planning Low

VIOLATES if the file describes multi-step tasks without guiding the agent to plan or decompose before acting.

Why it matters — Unplanned multi-step work drifts and stalls.

openai-persistence Medium

VIOLATES if the file asks the agent to complete tasks but permits stopping early without finishing or verifying the work.

Why it matters — Agents stop at the first plausible answer unless told not to.

Cursor 6 standards

cursor-scoped Medium

VIOLATES if the file is bloated with rambling or tangential content rather than concise, scoped instructions.

Why it matters — Every wasted token crowds out code context.

cursor-specific-refs Low

VIOLATES if it points to "the relevant files" or "the config" vaguely instead of naming specific files or paths.

Why it matters — Named paths are actionable; "the config" is a guess.

cursor-declare-conventions Medium

VIOLATES if the project's stack, build/test commands, or core conventions are never declared.

Why it matters — The first thing an agent needs is how to build and test.

cursor-one-concern Low

VIOLATES if a single section tries to govern many unrelated concerns that should be split.

Why it matters — Mixed sections are half-read and half-applied.

cursor-no-stale-blanket Low

VIOLATES if it contains always-apply guidance that is over-broad, outdated, or no longer matches the described project.

Why it matters — Stale blanket rules teach the agent to distrust the file.

cursor-code-style-examples Low

VIOLATES if it mandates a code style without showing a concrete example of compliant code.

Why it matters — Style is imitated from examples, not adjectives.

Karpathy / community 4 standards

community-success-criteria Medium

VIOLATES if tasks are described without any definition of done or success criteria.

Why it matters — Without "done", agents under- or over-shoot.

community-no-dead-context Low

VIOLATES if it includes reference content that is never connected to any instruction or used by any task.

Why it matters — Dead context costs tokens and buys nothing.

community-single-source Medium

VIOLATES if the same topic is governed by guidance scattered across multiple places that could drift out of sync.

Why it matters — Duplicated guidance always eventually contradicts itself.

community-concrete-over-abstract Low

VIOLATES if key guidance stays abstract where a concrete rule, value, or example is clearly needed.

Why it matters — Concrete rules are checkable; abstractions are vibes.
