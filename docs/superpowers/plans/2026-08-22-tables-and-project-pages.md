# Tables, project pages and ranked analytics — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every task also follows the project skill `shipping-a-feature`.

**Goal:** Replace card/collapsible layouts with one shared sortable, searchable, pill-filtered table; give every project its own page; rework Rules into tabs + a separate add flow; turn the Usage chart into ranked bars.

**Architecture:** A `DataTable` wrapper over headless TanStack Table (+ virtual) and a `Tabs` and `RankedList` component ship first; screens are rebuilt on them with pure column/pill definition files per screen. Four small Rust read-model additions feed the new columns. Routes `projects`, `project`, `rules-new` are added to the existing string-union router.

**Tech Stack:** React 18 + TS, `@tanstack/react-table` v8, `@tanstack/react-virtual` v3, Vitest + Testing Library + vitest-axe, Storybook 8, Rust/rusqlite + tauri-specta.

**Spec:** `docs/superpowers/specs/2026-08-22-tables-and-project-pages-design.md`

## Global Constraints

- Rust gates: `cd src-tauri && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`. Frontend gates: `pnpm lint && pnpm typecheck && pnpm test && pnpm storybook:build`.
- IPC types use `i32`/`u32`/`f64`/`String`/`bool`; `src/lib/bindings.ts` is regenerated by `cargo test` and committed, never hand-edited; new types re-exported from `src/lib/ipc.ts`.
- Component folders: `index.ts`, `<Name>.tsx`, `<Name>.types.ts`, optional `.constants.ts`, test, story; hooks in `use<Name>.ts`; pure helpers in `<name>.util.ts` with tests. Screens never import `claude_code::`-specific paths.
- Styling via CSS custom properties in `src/styles/tokens.css`; no Tailwind/shadcn in the app.
- Every table: search (debounced 150 ms), pills (AND across groups, OR within), tri-state header sort with `aria-sort`, sticky header, empty-filtered state "No rows match — clear filters", state remembered per table key in `sessionStorage`.
- Every PR updates `docs/status/data.json` + `pnpm status`.
- Existing tests keep passing or are updated faithfully when a screen is replaced.

export function columnsFor(kind: ArtifactKind, ctx: { onOpen: (fileId: string) => void; projectNames: Map<string, string> }): ColumnDef<ArtifactView>[]   // per spec §4.1 table

**Memoisation (from PR 1 review):** `DataTableProps.columns/pills/search` are documented as
identity-stable — `columnsFor`/`pillsFor` must therefore hand back the *same* array for the
same inputs, not a fresh one per render. Build a module-level cache keyed by kind (plus the
context the defs close over) and return from it; a screen that calls `columnsFor(kind)` inline
would rebuild the column model, the filtered set and every chip count on every keystroke. The
table's memos also key on pill group ids and search key count, so a cache that returns a
stale-but-stable array is caught — but only for shape changes, not for content.
